# Third-party software in Elm OS

Elm OS's own code (everything in this repository unless a file says otherwise) is under the
MIT license in [LICENSE](LICENSE). An Elm OS image also contains other people's software,
which keeps its own license. This file lists it. The image carries this file, LICENSE and
every license text named below in `/usr/share/licenses/elmos/` (the `make` rule for
`build/licenses/.done` collects them; most come from [licenses/](licenses)).

Every version below is pinned in `versions.mk`, `alpine.lock`, `host/Cargo.lock` or
`elm/elm.json`, so the exact sources of any image can be found from its commit
(`/etc/elmos/commit`, shown on the About page).

## Linux (the kernel)

GPL-2.0 with the Linux syscall note (`linux-COPYING`, `linux-GPL-2.0`, `linux-syscall-note`).
Elm OS's programs only talk to the kernel through system calls, so the GPL doesn't reach them.

Source: the stable tag `KERNEL_VER` in `versions.mk` from
<https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git>, unmodified, built with
the configuration in `kernel/elmos.config` (the `Makefile` shows how). Anyone who receives an
Elm OS image can get exactly this source and configuration from this repository at the image's
commit; whoever distributes images should keep that possible for at least three years (for
example by keeping the repository public), as the GPL asks.

## Firmware (USB images only)

Loaded by the kernel, from Alpine Linux's `linux-firmware-*` packages (`alpine.lock`).
Redistributable only unmodified, and only with their license:

- Intel GPU (i915): `firmware-LICENSE.i915`
- Intel wifi (iwlwifi): `firmware-LICENCE.iwlwifi_firmware`
- NVIDIA GPU (nouveau): `firmware-LICENCE.nvidia`. Its open source exception allows
  redistribution only for use on operating systems under an OSI-approved license, which is
  why Elm OS's own code being MIT matters here.

## wpa_supplicant (joins wifi networks)

BSD-3-Clause (`wpa_supplicant-README`), built from the release tarball `HOSTAP_VER` in
`versions.mk`, unmodified. It is statically linked with **libnl 3** from Alpine, which is
LGPL-2.1-or-later (`libnl-COPYING`). The LGPL lets you replace libnl in a static program
as long as you can relink it: this repository's `Makefile` builds `/usr/sbin/wpa_supplicant`
from source, so anyone can rebuild it with a different libnl.

hostapd, the simulated access point, is only in the QEMU test image, never on a USB stick.

## Mesa and the GPU renderer's libraries (when built with GPU=1)

Shared libraries copied from Alpine Linux 3.22 packages (`alpine.lock`) by
`tools/copy-libs.sh`, unmodified. Their sources are Alpine's
(<https://gitlab.alpinelinux.org/alpine/aports>, at the pinned package versions).

| Package | License (Alpine's) |
| --- | --- |
| mesa (EGL, GLES, GBM, Gallium drivers) | MIT AND SGI-B-2.0 AND BSL-1.0 (`mesa-MIT`, `mesa-SGI-B-2.0`, `mesa-BSL-1.0`) |
| musl (the dynamic loader) | MIT (`musl-COPYRIGHT`) |
| libdrm, libexpat, libffi, libxml2, libxcb, libxau, libxdmcp, libxshmfence, wayland-libs | MIT |
| libx11, libpciaccess | X11 |
| libbsd, libmd | BSD-3-Clause (libmd also BSD-2-Clause, ISC, Beerware, public domain) |
| zlib | Zlib |
| zstd-libs | BSD-3-Clause OR GPL-2.0-or-later |
| xz-libs (liblzma) | 0BSD / public domain for the library |
| spirv-tools | Apache-2.0 |
| libelf (elfutils) | GPL-2.0-or-later OR LGPL-3.0-or-later, dynamically linked |
| libstdc++, libgcc (GCC) | GPL-3.0 with the GCC Runtime Library Exception |

Alpine's packages don't carry their license texts, so apart from Mesa's and musl's they are
not yet in the image: this is the known gap in this list. libLLVM is not shipped: Elm OS
replaces it with a stub of its own (`tools/llvm-stub.sh`).

## Rust crates (in /init and the GPU renderer)

All under permissive licenses (MIT, Apache-2.0, ISC, BSD-3-Clause, Unicode-3.0, and
CDLA-Permissive-2.0 for `webpki-roots`, Mozilla's list of certificate authorities).
`rust-crates.txt` lists each crate with its license and carries their license texts,
generated by `tools/rust-licenses.py` from `host/Cargo.lock`.

## The Elm program (/usr/lib/elmos/elm)

- Elm packages compiled in (`elm/elm.json`): elm/core, elm/bytes, elm/json, elm/time,
  elm/parser, ianmackenzie/elm-units, justinmimbs/date, rtfeldman/elm-hex and eco/containers
  (vendored in `eco-containers/`), all BSD-3-Clause (`elm-packages.txt`).
- eco's runtime and kernel libraries, linked in by the eco compiler (`ECO_VER` in
  `versions.mk`, <https://github.com/eco-lang/eco-compiler>). eco's compiler and
  `system-kernel-cpp` are BSD-3-Clause, and its runtime bundles parts of LLVM's libc
  (Apache-2.0 WITH LLVM-exception) and Unicode data (Unicode license): `eco-runtime.txt`.
  **Open question:** at the pinned release, eco's `runtime/`, `elm-kernel-cpp/` and
  `eco-kernel-cpp/` directories have no license file, and the repository has none at its
  root. They are compiled into every Elm OS image, so eco's authors need to state their
  license.
